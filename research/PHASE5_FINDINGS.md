# A7C II 2.01：逐路径 MLUT 开关的数据流

后续 [PHASE6_FINDINGS.md](PHASE6_FINDINGS.md) 已确认真实初始化还会生成 `[0,0,0,0]` 的重复映射，并补充验证；本阶段的 384 组排列实验不是全部实际情况。

延续 [提交接口研究](PHASE4_FINDINGS.md)。本轮新增的是输出路径参数传递证据，**不是 JPEG 效果验证**。未连接、修改或刷写相机。

## 已追通部分

1. `Sequence_WritePin.cpp` 相关代码在 `0x4d281e` 开始读取参数构建输出：MLUT ID、CP 模式、base_look、色域等。
2. `0x4d2880–0x4d289c` 按对象 `+0x370` 的映射表读取四个标志：`object + 0x1c4 + 0x70 * mapping[i]`，写入临时参数结构 `+0xc8+i`。因此不能直接将原始标志的顺序当成下游路径顺序。
3. 调用 `0xb2f432` 时会尾跳转到 `0x13dc70`；后者 `0x13e604–0x13e612` 将临时参数 `+0xc8` 起的 100 字节复制到共享配置 `0x173f1e8`。
4. 下游 `0x4e0ad2` 读取共享配置的逐路径字节：为零跳至 `0x4e0df0`，非零进入一段 MLUT 配置处理。该段还按 MLUT ID 分支修改处理参数，随后调用 `0x688954` 等函数，并恢复暂存字段。

共享配置的已关联布局：

| 相对 0x173f1e8 的偏移 | 来源 |
| --- | --- |
| +0..3 | 重排后的四个标志 |
| +4 | 参数构建输出 +0x13b8：MLUT ID |
| +8 | +0x13bc：CP shooting_mode |
| +0xc | +0x13c0：有效 base_look |
| +0x10 | +0x13c4：color_gamut |
| +0x14 | +0x13c8：尚未完全解释的参数 |

日志中的源文件名 `Sequence_WritePin.cpp` 位于 `0x4d2c78`；不能仅凭 WritePin 名字认定它就是静态 JPEG 写卡流程。

## 验证与边界

新增 `emulate_mlut_routing.py`，执行三段原始指令：参数/标志拷贝、原始 memcpy 共享配置复制、逐路径分支判断。

- 全部 16 种二值标志组合 × 24 种排列，共 **384 组通过**。
- 对每组检查重排结果、共享配置字节一致性，以及四个分支目标。
- 这些是**显式设置寄存器入口的局部指令片段仿真**，没有冒充完整函数执行或真实调度。
- 排列表、上下文及标志是合成输入；没有证明真机映射只包含 0–3 的排列。真实调用附近另有 `0xff` 路径哨兵判断，需要单独分析。
- 路径编号 0–3 的语义仍未确认，不能把其中一个直接标成 JPEG，也不能据此认定照片支持 LUT。

产物：`a7c2-2.01/cp-mlut-routing.json`；新增完整函数导出 `0x13dc70–0x13e6bc`。当前自动化测试为 19 项，覆盖字节一致性和代表性路由用例；384 组完整矩阵由上述脚本单独运行。
